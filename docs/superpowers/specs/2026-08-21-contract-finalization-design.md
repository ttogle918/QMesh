# 계약 문서 확정 — 설계 (2026-08-21)

## 배경

QMesh(A2A_Q)는 FinAllQ·InsuQ·MaintQ 세 프로젝트를 A2A로 잇는 계약 계층(Agent Card 3종·
Task 스키마 12종)을 이미 보유하고 있다. 어댑터 구현(각 레포에 A2A 창구를 여는 작업)은
각 레포가 자체 구현을 어느 정도 마친 뒤로 미루기로 했고, 이번 작업은 **그 전에 계약
문서 쪽의 미정리 상태 3가지를 확정**하는 것이다.

세 레포(FinAllQ·InsuQ·MaintQ)는 `../FinAllQ`, `../InsuQ`, `../MaintQ`에서 이 세션 중
읽기 접근이 허용됐다 — 타 프로젝트 파일 변경이 필요해지면 그때 먼저 확인을 구한다.
이번 작업 범위 내에서는 타 레포 코드 변경이 필요 없다(문서·스키마 편집은 전부
A2A_Q 안에서 끝난다).

## 범위

### ① CP-001 → 채택
`docs/A2A_CONTRACT_CHANGES.md`가 기록한 CP-001(InsuQ 스킬 5종: 거부 표현·근거 인용
표준화)은 세 레포 전수 확인 결과 참조 코드 0건이라 위험 없이 지금 확정 가능하다.

- 영향받는 스키마 5개 파일(`advise-policy-renewal.json`, `verify-collateral-insurance.json`,
  `notify-asset-change.json`, `notify-risk-change.json`, `claim-insurance.json`)에서
  `description` 필드에 붙은 `PROPOSED(InsuQ, 2026-08-19): ` 접두사(총 10곳)를 제거한다.
  설명 본문은 그대로 둔다 — 스키마 자체(내용)는 이미 CP-001을 반영해서 작성돼 있었고,
  바뀌는 건 "제안" 표시뿐이다.
- `A2A_CONTRACT_CHANGES.md`의 CP-001 상태 표를 `🟡 제안 — MaintQ·FinAllQ 확인 대기`에서
  `🟢 채택 (2026-08-21)`로 바꾼다.
- "각 프로젝트가 확인할 것" 체크리스트(MaintQ·FinAllQ 항목)는 **체크하지 않는다** —
  그건 각 레포가 실제 구현하며 스스로 확인할 일이지, 문서 확정이 대신할 수 없다.

### ② A2A_IDENTITY.md 미결 사항 5개 재정리
"여전히 남아있는 미결 사항" 절의 5개 항목을 다시 읽어보면:

- #1(MaintQ 대리 여부), #2(파트너 자격증명 발급 주체·연결 절차), #3(대출심사가 조언인가
  실행인가) — **이미 본문에 결론이 적혀 있다.** "미결" 표제 아래 묻혀 있어 헷갈릴 뿐이다.
  → 각 항목 앞에 `✅ 해결됨`을 붙이고, 이미 있는 결론 문단을 그대로 둔 채 위치만
  명확히 한다.
- #4(출금 요청이 기존 이체 파이프라인을 타는지), #5(감사 로그에 외부 actor를 어떻게
  남기는지) — 원문에 이미 "미해결 — FinAllQ 구현 시 결정"이라 적혀 있다. **QMesh가
  지금 대신 결정할 수 없는 항목**이다.
  → `⏸ FinAllQ 구현 착수 시 결정 (QMesh 비차단)`으로 라벨을 명확히 하고 내용은
  그대로 둔다.

이 작업은 결론을 새로 만드는 게 아니라 **이미 있는 결론과 진짜 미결을 구분해서
드러내는 것**이다.

### ③ 문서 구조 정리 (중복·drift 점검)
사전 확인 결과:
- `docs/schemas/` 12개 파일 = `docs/agent_cards/*.json` 3개 파일에 선언된 스킬 id 12개
  = `README.md` §2의 스키마 목록 12개 — **정확히 일치, drift 없음.**
- `docs/ref_insuq/`·`docs/ref_maintq/`·`docs/ref_finallq/` 세 인덱스 문서 모두
  "실제 스키마 원본은 A2A_Q에 있고 복제하지 않는다"는 원칙을 일관되게 지키고 있다.

→ 새로 발견되는 구조적 문제가 없으면 **"점검 완료, 변경 없음"으로 마무리**한다.
점검 중 실제 drift나 모순을 발견하면 그 자리에서 고치고 이 스펙에 기록을 남긴다.

## 하지 않는 것 (범위 밖)
- FinAllQ·InsuQ·MaintQ 레포의 코드·문서 변경 (이번 라운드는 A2A_Q 내부 문서만)
- 어댑터/오케스트레이터 실제 구현 (사용자가 명시적으로 뒤로 미룸)
- CP-001 이후의 새로운 계약 변경 제안(CP-002 등) — 이번엔 기존 CP-001 확정만

## 완료 기준
- CP-001 관련 스키마 5개 파일에 `PROPOSED(...)` 문자열이 더 이상 없음
- `A2A_CONTRACT_CHANGES.md`의 CP-001 상태가 `채택`으로 바뀜
- `A2A_IDENTITY.md`의 미결 사항 5개가 해결됨/보류 라벨로 재분류됨
- 문서 구조 점검 결과가 기록됨(변경 없음이든, 발견한 수정이든)
