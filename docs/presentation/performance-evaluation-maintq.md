## 🏗️ 기술 스택

### 아키텍처

```
Frontend (Next.js)
    ↓
Backend (FastAPI + Python 3.13, uv)
    ↓
AI Engine (Gemini 2.5 Flash)
    ↓ (MCP)
MCP Server (7코어 + 11확장 도구)
    ↓
Postgres (25개 테이블, pgvector 포함 — 2026-08-24 Sprint 16(D116)에서 SQLite 목업 DB 로부터 전환)
```

> **2026-08-24 갱신.** 아래 표의 "SQLite 목업" 행은 전환 이전 기록입니다 — DB 자체는 Postgres로, 매뉴얼 검색은 키워드+dense 임베딩 하이브리드(D117, NVIDIA API)로 바뀌었습니다. 표를 그대로 두고 이 문단만 덧붙입니다 — 아래 성능 평가 수치는 이 전환과 무관한 이전 측정값입니다.

### 사용 패키지 & 기술 선택

| 기술 | 구성 | 선택 이유 | 효과 |
|---|---|---|---|
| **FastAPI** | 비동기 웹 프레임워크 | SSE(Server-Sent Events) 네이티브 | 도구 실행 중 실시간 토큰 스트림 |
| **Gemini 2.5 Flash** | LLM | 레이턴시 안정적 (p95 10.4s) | 평가 기준 충족, 외부 API 호출 효율 |
| **Anthropic Agent API** | 도구 루프 자동화 | for 루프 수동 구현 제거 | 토큰 40% 절감, LLM 호출 간결화 |
| **MCP (Model Context Protocol)** | 도구 표준화 | 백엔드 코드 수정 없이 도구 교체 | ERP 마이그레이션 시 MCP 서버만 갈아끼우면 됨 |
| **SQLite 목업** | 데이터베이스 | 실제 ERP와 동일 스키마 | 로컬 테스트, 쉬운 마이그레이션 경로 |
| **pydantic v2** | 데이터 검증 | C 확장 + 타입 안전성 | 성능 40% 향상, 런타임 오류 조기 감지 |

```python
display_error = "e3" if user_input == "e3" else "E3"
```

**효과:** 사용자 입력 무관하게 일관된 매칭

### 사례 2: Agent API 토큰 절감

**기존 (수동 도구 루프):**
```python
for turn in range(max_turns):
    response = llm.complete(messages, tools=[...])
    # 매 턴마다 full context 전달
    # 도구 결과도 messages에 추가하고 재호출
```

```python
response = client.messages.create(

    max_tokens=4096,

```

## 🏆 설계 철학

### 3가지 절대 원칙

1. **근거 기반 판단**
   ```
   AI가 준비 (근거와 함께)
   ↓
   사람이 결정 (서명)
   ↓
   최종 실행 (확정 단계에서만)
   ```

2. **명확한 의도 코딩**
   ```
   스키마가 규칙을 강제한다
   예: 쓰기 권한을 커넥션 레벨에서 격리
       판정(link_state)과 식별자(external_ref) 분리
   ```

3. **재현성 우선**
   ```
   데이터가 정본
   파생값은 없다
   과거 trace 원문은 그 시점 그대로
   ```
