## 5. 설계 — 자동 폴백, 그리고 judge 예외

`docs/superpowers/specs/2026-08-29-llm-provider-unification-design.md`.

핵심 결정 셋:

1. **재시도와 폴백을 분리한다.** 401/403/404는 재시도 없이 즉시 폴백, 402/429는 1회,
   5xx·미분류는 기존 정책 소진 후. 401에 3번 백오프하는 건 순수 낭비고, 일시적 5xx에
   곧장 유료 경로로 넘어가면 돈이 샌다. (부수 효과로 **기존 버그**가 드러났다 —
   `except (RateLimitError, APITimeoutError, APIError)`에서 `APIError`가 SDK 최상위라
   **401도 3회 백오프하고 있었다.**)
2. **전환을 조용히 하지 않는다.** WARN 로그 + `LLMTurn.provider_used`. 없으면
   "왜 이번 달 청구서가 있지"가 된다.
3. **평가 judge는 폴백하지 않는다.** 실행 중간에 judge가 갈리면 앞뒤가 다른 모델로
   채점된 리포트가 나오는데 **겉보기엔 정상**이다. 서빙은 "죽는 것보다 비싼 게 낫다",
   평가는 "오염된 숫자보다 실패가 낫다".

③은 계획을 쓰다가 **특례 코드 없이 구조로 해결**됐다 — 폴백 설정을
`_apply_generation_override()`(서빙 전용)에서만 읽으면 `eval/run.py`가 그 함수를 타지
않으므로 평가 경로에는 폴백이 아예 존재하지 않는다. `build_judge_client()`를 손댈
필요가 없어졌다.

### 내가 틀린 것 (기록해 둔다)

**나는 합성 재현을 44회 돌려 전부 정상이 나오자 "기각이 이르다"고 밀었다. 이건

정상이라는 건 **내 재현이 그 파이프라인이 아니라는 증거**지 그쪽 발견이 의심스럽다는
증거가 아니다. 사용자가 "재현을 못했는데 그냥 기각 안 하겠다는 거지?"라고 짚어서
바로잡았다.

**내가 제안한 두 지렛대가 둘 다 역효과였다:**

| 제안 | 실제 결과 |
|---|---|
| `thinking=false` (nemotron) | 🔴 **4/4 빈 본문** + `finish_reason=tool_calls` — `tools`를 생략했는데도 도구를 원하는 D14a quirk 발동. 본문이 비는 게 정당한 상태(D20)라 **예외조차 안 나는 더 조용한 실패** |
| `reasoning_effort=low` (gpt-oss) | 🔴 크래시는 사라지나 게이트 4/6, **답변 자리에 도구 호출 인자 JSON이 퇴행 반복 토큰과 함께 누출**. 크래시보다 나쁘다 |

## 8. A안 확정 — 통일 목표를 증거에 맞춰 포기했다

| | 기본 | 폴백 |
|---|---|---|
| **MaintQ** | `nvidia` / `openai/gpt-oss-120b` (무료) | `openai` / `gpt-4.1-mini` |
| **InsuQ** | `openai` / `gpt-4.1-mini` | **없음(의도적)** |

원래 요청은 "맞추자"였지만 증거는 **두 시스템이 같은 모델을 요구하지 않는다**고
말했다. 억지로 통일하면 한쪽이 깨진다. 유료 경로는 둘 다 `gpt-4.1-mini`로 같아졌으니
"모델 통일"은 절반 지켜진 셈이다.

**InsuQ 폴백을 비운 것도 의도적이다** — 유일한 대안이 게이트를 통과 못 하므로,
켜두면 장애 시 더 나쁜 모델로 떨어진다. `FallbackLLMClient` 코드는 휴면 상태로 남고
("폴백 미설정 = 기존 동작"이 테스트로 지켜진다) 다음 제공자 전환 때 그대로 쓴다.

**버려진 작업은 없다.** InsuQ Task 1(401 재시도 버그 수정)은 폴백과 무관한 진짜
버그 수정이고, MaintQ는 실제로 무료 경로로 돌아간다.
